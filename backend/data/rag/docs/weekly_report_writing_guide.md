# 员工周报撰写规范与模板说明

> 文档类型：制度文件 | 分类：周报 / 工作总结 | 适用：全体项目成员  
> 检索关键词：周报怎么写、要写哪些项、本周工作总结、周报格式、执行内容汇总

---

## 一、周报目的与适用范围

周报用于记录**自然周**（周一至周日）内的工作进展、执行内容与下周计划，供本人复盘、直属上级了解进度、项目组同步风险。

适用人员：参与项目任务、执行分工的所有成员。  
提交频率：**每周五 18:00 前**（或按项目约定）提交上一自然周周报。

---

## 二、周报必须包含哪些项（必填章节）

一份完整周报须包含以下 **6 个章节**，缺一不可：

| 序号 | 章节名称 | 说明 |
|------|----------|------|
| 1 | 本周工作概述 | 1～3 句话概括本周主线 |
| 2 | 本周完成任务 | 列出已关闭/已完成的任务（含任务 ID 或标题） |
| 3 | 执行内容明细 | 各任务下的执行分工/子项完成情况（**必填**） |
| 4 | 进行中与待办 | 未完成任务、阻塞项、风险 |
| 5 | 问题与所需支持 | 需协调的资源、决策、跨部门事项 |
| 6 | 下周工作计划 | 3～5 条可验收的下周目标 |

---

## 三、各章节怎么写（写作要点）

### 3.1 本周工作概述

- 用 **第一人称** 或 **姓名+角色** 开头，例如：「本周主要参与 XX 项目，完成需求分析与接口开发。」
- 避免空泛表述（如「本周工作很多」），应点出 **项目名 + 主要产出**。

### 3.2 本周完成任务

每条任务建议包含：

- **任务标题**（或任务 ID）
- **所属项目**
- **完成状态**（已完成 / 已验收）
- **完成时间**（日期）
- **简要结果**（1 句话）

示例：

```text
- 【任务#1024】完成需求文档 v1.2 评审（项目：企业协作平台，5/22 完成）
- 【任务#1031】代码评审 3 次，均已通过（项目：移动端改版，5/24 完成）
```

### 3.3 执行内容明细（重点）

「执行内容」指任务分解后的**具体分工项**（子任务、检查项、交付物），不是只写任务名。

每条执行内容建议包含：

| 字段 | 是否必填 | 说明 |
|------|----------|------|
| 关联任务 | 是 | 任务标题或 ID |
| 执行内容标题 | 是 | 分工项名称 |
| 完成情况 | 是 | 已完成 / 进行中 / 未开始 |
| 产出物 | 建议 | 链接、文档名、PR 号 |
| 工时或进度 | 可选 | 如「约 8h」「80%」 |

示例：

```text
任务「接口开发」下执行内容：
  - 用户模块 API 设计与实现 — 已完成，已合并 PR #456
  - 单元测试补充 — 进行中，覆盖率 65%
  - 接口文档更新 — 未开始，计划下周二完成
```

**若本周无已完成任务，仍须写执行内容**：说明各分工项推进到哪一步。

### 3.4 进行中与待办

- 列出 **未完成** 但本周有推进的任务
- 标注 **逾期** 任务及原因（需求变更 / 依赖阻塞 / 资源不足）
- 风险须具体：「依赖后端接口 5/25 交付」优于「进度有风险」

### 3.5 问题与所需支持

- 仅写 **需他人协助** 的事项
- 格式：问题 + 影响 + 期望支持方 + 期望时间

### 3.6 下周工作计划

- 每条计划应 **可验收**（避免「继续开发」）
- 建议与本周未完成项、项目里程碑对齐

## 四、按项目维度汇总（多项目成员必读）

若成员**同时参与 2 个及以上项目**，须二选一（提交前确认）：

**方式 A — 分项目周报（推荐）**  
每个项目单独一份，结构仍含上述 6 章，任务/执行内容**仅写该项目**。

**方式 B — 总周报 + 分项目附录**  
主文档写 6 章总览；附录按项目列出任务与执行内容明细。

> Agent 生成周报时：若检测到多项目任务，应询问用户选择 **「单项目」** 还是 **「全部项目总周报」**。

---

## 五、时间范围约定

- **「本周」**：当前自然周周一至周日（以系统日期为准）
- **「上周」**：上一自然周
- 统计任务时默认过滤：`updated_at` 或 `completed_at` 落在该周内
- 执行内容：本周有 **状态变更或产出** 的分工项均应纳入

---

## 六、周报输出格式模板（可直接填充）

```markdown
# 周报 — {姓名} — {YYYY-MM-DD} 至 {YYYY-MM-DD}

## 1. 本周工作概述
{概述}

## 2. 本周完成任务
{任务列表}

## 3. 执行内容明细
{按任务分组的执行内容}

## 4. 进行中与待办
{列表}

## 5. 问题与所需支持
{列表或「无」}

## 6. 下周工作计划
{列表}
```

---

## 七、质量检查清单（提交前自检）

- [ ] 6 个必填章节均已填写
- [ ] 至少 1 条 **执行内容明细**（非仅任务名）
- [ ] 任务与项目归属清晰
- [ ] 逾期/风险已说明原因
- [ ] 下周计划可验收
- [ ] 多项目已按第四节规则拆分或说明

## 八、常见问题 FAQ

**Q：周报怎么写 if 本周只做了会议和沟通？**  
A：写入「执行内容明细」，会议可记为分工项，注明结论与待办。

**Q：要写哪些项 if 任务还在进行中？**  
A：必须写「进行中与待办」+ 已有推进的「执行内容明细」，不可留空。

**Q：能否用 bullet 代替表格？**  
A：可以，但须包含：任务、项目、执行内容、状态四要素。

**Q：Agent 自动总结本周工作时应查哪些数据？**  
A：优先查询：① 本周更新的任务列表；② 各任务下执行分工/执行内容；③ 可选：评分、评价记录。

---

## 九、与任务系统的字段对应关系

| 周报章节 | 系统数据来源 |
|----------|--------------|
| 本周完成任务 | 任务表 status=已完成/已关闭，completed_at 在本周 |
| 执行内容明细 | 执行分工表 execution / 子任务，本周有更新 |
| 进行中与待办 | 任务 status=进行中/待处理，deadline 在本周或已逾期 |
| 所属项目 | 任务.project_id → 项目名称 |

## 十、示例摘要（供 RAG 检索参考）

**示例问法**：「帮我总结一下这周都做了些什么」  
**Agent 应执行**：检索本规范 → 查询本周任务与执行内容 → 按第六节模板生成 → 多项目时按第四节确认范围。

**示例问法**：「周报要写哪些项？」  
**应答要点**：六大章节 + 执行内容明细为必填 + 多项目分项目汇总。
